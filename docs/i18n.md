# Languages (English and Kiswahili)

MEDVERSE is bilingual from Phase 1: every interface message and every new piece of
content is written in English and Kiswahili. English is the source language; Kiswahili
must keep the same meaning, and medical terms stay checkable against the international
(Latin / Terminologia Anatomica 2) term.

> **Status of the Kiswahili text.** All Kiswahili is a **draft translation** until it has
> been reviewed by a Swahili-speaking health professional (see *Review* below). The app
> says so wherever translated content appears.

## How the language is chosen

- Every page lives under `/en/…` or `/sw/…`. Both are prerendered, so each language is
  cached separately (important for offline use) and links can be shared in either language.
- Un-prefixed URLs (old links, bookmarks) are redirected by `frontend/src/proxy.ts` using
  the saved preference (`mv_locale` cookie, set by the language switcher), then the
  browser's languages (`sw`, `sw-KE`, `sw-TZ` … count as Kiswahili), then English.
- The switcher (sidebar and sign-in pages) reloads the same page in the other language.
- The frontend sends `Accept-Language` with every API request; the backend answers in
  that language where a translation exists.

## Interface messages

`frontend/src/lib/i18n/messages/en.ts` (source) and `sw.ts`. The `Messages` type makes a
missing or extra Kiswahili key a type error, and `i18n.test.ts` checks that placeholders
match and that no message was copied untranslated.

```tsx
const { t, tp } = useT();
t("dashboard.welcomeName", { name });     // placeholders: {name}
tp("learn.viewSystems", count);           // picks viewSystems_one / _other by plural rules
<Link href="/learn">…</Link>              // from @/lib/i18n/client: keeps the language
```

Server components (layouts, `generateMetadata`) use `messagesFor(lang)`. Under Cache
Components, metadata must not read a dynamic segment such as `[moduleId]`, so the module
page title is set by `learn/layout.tsx`, whose params hold only `lang`.

The whole interface is translated: shell, sign-in (including form validation), dashboard,
learning hub and modules, quizzes, the 3D explorer (toolbars, panels, layer presets,
structure and body-map panels, 3D quiz, playback), the cell-scale labs, and the
physiology and pathology labs. The wording of the living processes and brain/neck
pathways is in `frontend/src/features/biolab/text.sw.ts`, matched to the English steps by
position (structures and timing stay in the English source; a test checks they line up).

## Content

Content translations live beside the English content, by item id:

| File | Translates | English source |
|---|---|---|
| `content/i18n/sw/systems.json` | system `name`, `description` | `content/systems.json` |
| `content/i18n/sw/modules.json` | module `title`, `tagline` and any body field | `content/learning/modules.json` |
| `content/i18n/sw/questions.json` | quiz `stem`, `options`, `explanation` | `content/learning/quizzes.json` |
| `content/i18n/sw/structures.json` | structure `name` | generated structures |
| `content/i18n/sw/models.json` | simulation model `name`, `summary`, `purpose`, `disclaimer`, parameter and output labels (by id), 3D animation notes, phase plots | `backend/app/simulation/models` |
| `content/i18n/sw/conditions.json` | condition narrative fields and scenarios (by id) | `content/pathology/conditions.json` |

Each item is a **partial copy** of the English item with the same shape: dictionaries by
key, lists in the same order. Fields left out are shown in English, and the API marks
the item `"translation": "partial"` so the app can say *"parts of this module are shown in
English"*. Identifiers, links and international names (`structure_id`, `system`, `latin`,
`latin_name`) are never translated.

The seed (`backend/app/seed/loader.py`, `seed_translations`) loads the files into
`content_translations` and **fails on a stale id or a misspelt field**, so translations
cannot silently drift from the English content.

Current coverage (draft): all system names and descriptions; all 12 modules in full;
all 84 quiz questions; the names of the 69 structures that modules and quizzes point to;
the user-facing text of the 4 simulation models; both pathology conditions and their
scenarios.

Deliberately kept in English:

- **Structure names in the 3D explorer** (about 2,500), with their Latin (TA2) names. English
  and Latin are the language of anatomy teaching in East African health-professions
  schools, and a half-translated explorer would mix languages. Module organ cards and
  quiz answers do use the Kiswahili names above.
- **Technical model documentation** (equations, solver, assumptions, limitations,
  validation); the lab says so in Kiswahili. Units and symbols are not translated.
- **Curated structure content** and run-time simulation warnings: not yet translated.

## Writing and review

1. Write the English text, then the Kiswahili text in the same change.
2. Prefer established Kiswahili medical terms (as used in Kenyan and Tanzanian health
   training); where none is established, keep the international term and explain it in
   Kiswahili (e.g. *alveoli*, *nefroni*).
3. Keep numbers, units (SI) and drug names unchanged.
4. **Review:** a Swahili-speaking clinician or health educator checks meaning and
   terminology; the file's `"status"` moves from `"draft"` to `"reviewed"` only after that,
   following the content governance process ([content-governance.md](content-governance.md)).
